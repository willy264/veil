## Screenshot critique and repeat

The first 1440/390px pass preserved the green identity and removed equal-card gaps, but a wordmark accessible label omitted Testnet. The label was fixed. Review also retained the numbered paths, unobstructed input widths, secondary auditor controls and clear Example label. [First pass](../results/ui-polish/first-pass/results.json).

The second screenshots cover both tabs. The QA runner itself initially failed on widths where Axe was intentionally skipped; optional access to the skipped result was corrected. The completed production rerun checked all 44 paths with no failures. [Second screenshots](../results/ui-polish/second-pass/), [final production screenshots and report](../results/ui-polish/final-pass/).

The initial Lighthouse performance score was 57. Loading the wallet connector only on Connect and near-api-js only on Spend reduced initial JavaScript transfers from 198,045 to 42,876 bytes; the final score is 98. A green V favicon fixes the former missing-icon request. [Baseline](../results/ui-polish/lighthouse-mobile.json), [final](../results/ui-polish/lighthouse-final-mobile.json).

Anti-pattern review: no palette/font change, gradients, glass panels, decorative metrics, equal feature-card grid, fake live records or pipe-string footer. Examples are labelled and are replaced by live data after keys are derived. Tokens contain the app's visual values; the standalone favicon repeats the same background/accent values because external SVG cannot inherit page CSS.

## Reproduce

```powershell
pnpm --dir apps/web build
pnpm typecheck
pnpm test
node apps/web/qa.mjs https://veil-eta-khaki.vercel.app --out results/ui-polish/recheck --wallet-chooser
node apps/web/demo-hosted.mjs --preflight
```

QA needs installed Playwright and @axe-core/playwright; module paths can be provided through `VEIL_PLAYWRIGHT_MODULE` and `VEIL_AXE_PLAYWRIGHT_MODULE`. The demo runner's default invocation is inert. `--execute` sends new testnet transactions, so use the existing evidence for review; it is not needed to view the recording.

The old green-UI video required re-recording because it showed the former six-panel layout. The [replacement product video](NARRATED-TOUR.md) now uses the captured signed flow and discloses the scripted signer. Dependencies remain documented in [DEPENDABOT.md](DEPENDABOT.md). No field performance, screen-reader user study or browser-extension approval coverage is claimed.
